# 教學型 Resource 固定規格（Learning Content Spec v1.0）

> 狀態：採用；日期：2026-11-18（Asia/Taipei）
> 參考範本：AI 工程決策速查表的「AI 系統設計」章節。
> 原始資料：data/resources/aiposthub-awesome-opensource-ai-cheat-sheets-guide.json
> 網站範例：https://christinekao.github.io/AI-Tool-Collection/index.html#/resources/aiposthub-awesome-opensource-ai-cheat-sheets-guide

## 目標與適用範圍

把工具／技術的介紹轉成「能選擇方案、解釋理由、動手練習、檢查成果」的教材。**重用的是教學邏輯與版面，不是硬複製 AI 系統設計的技術內容。**

- 適用：已查核原始來源、值得提供深入教學的 Resource，或日後明確採用此格式的學習頁面。
- 不適用：單純工具收藏卡、尚未查核的來源、沒有足夠內容可以建立教學的資源。不要為了套格式硬湊章節。
- Source of Truth：資料以 data/resources/<id>.json 的 Canonical Record 為準，生成的 data/catalog-v2.json 不是手動修改處。
- 寫作語言：繁體中文；保留必要英文專有名詞；標示資訊來源、版本、假設與未驗證事項。

## 1｜頁面固定閱讀順序

1. **標題、標籤、來源連結**：快速辨識資源，不再額外重複一整段用途摘要。
2. **適合什麼情境？**：說明誰在什麼問題下適用、能用來做什麼，以及不是什麼。避免將資源的參考用途寫成已經能執行的工具能力。
3. **主要功能**：列出相互獨立、可從來源核對的具體內容或能力；不與上一段逐字重複。
4. **使用條件**：列出理解或實作所需前提；閱讀條件與實際部署條件要區分。
5. **限制與注意事項**：清楚區分來源宣稱／已檢查／已實測、時效性、安全、授權與依賴。
6. **主教材／章節筆記**：讓使用者在本站直接學習；章節數隨素材而定，不固定必須十章。
7. **整體練習與自我驗收**（有具體練習時）。
8. **原始資料與版本**（可展開查核，保留不同章節真實來源）。
9. **相關概念、Skills、實作參考** 等延伸資料：必要時放在教材後方。

對已採用此版型的 AI 工程決策速查表，頁面上的「適合什麼情境？／主要功能／使用條件／限制與注意事項」必須在「十個主題的重點筆記」**上方**。

**禁止重複的導讀區塊**：若標題、四段資源說明與正文已回答用途，不要再放長篇簡介、「學完能掌握什麼？」或「先看哪裡？」；除非有實際新增資訊且使用者明確要求。

## 2｜每一章的固定學習結構

### A. 章節標題 + 一個核心問題

- 以 **問題而不是工具名詞列表** 帶出學習目的：例如「這個需求真的需要 Agent 嗎？」
- 問題必須能在章節內獲得回答，避免只製造懸念。
- 可標示「先學／按需深入」，但不得再加入與正文重複的學習路線區。

### B. 需求 → 方案的判斷表（適用時）

- 有方案取捨時，使用「需求特性｜優先選擇」雙欄表，先從簡單可行方案列到複雜方案。
- 每列應有具體辨識條件及對應選擇，不是空泛優缺點列表。
- **只有真正存在可比較的方案才放表格**；一般概念解說不用硬湊。

### C. 三個判斷原則

依照「**先確認需求 → 比較方法與取捨 → 設定採用門檻／風險界線**」組織為三個遞進、互不重複的原則。

- 每項原則直接告訴讀者 **怎麼判斷、為什麼**；必要時點名工具類型、測試與限制。
- 有 decisionChecks 時，把對應問題寫在每項原則**下面**作為「檢查：……」，不要再做「真的需要 Agent？先回答這三個問題」等重複卡片。
- 檢查問題必須補充驗證角度，不能只是把原則改寫成問句。
- 若只有兩個真正不同的重點，不必填充假內容；寫作時應重新安排或調整章節粒度，而不是造出第三點。

### D. 情境例子

- 寫一個具體、合理的工作或學習情境，清楚展示 **需求 → 選擇 → 原因 → 適用界線**。
- 不要只有工具名稱與形容詞，也不要將假設情境說成真實案例或實測結果。
- 與其他章節例子有所區別，避免十章都換句話說同一個例子。

### E. 自己試試看

- 提供一個讀者當下可以做的小任務，至少包含 **操作／判斷動作 + 可交出的結果**。
- 可以是假設情境、手繪架構、比較表或測試案例；不要求先安裝無關工具。
- 練習必須對應該章的核心問題，不要要求讀者重複抄寫原則。

### F. 學完能產出

- 寫一個**可檢查的產物或決策紀錄**，例如選型理由、架構圖、測試表、風險清單、Release Gate。
- 避免「更了解 AI」、「掌握知識」等無法驗收的說法。
- 應能判斷練習是否達標；必要時增加通過／不通過準則。

章節呈現順序固定為：

**核心問題 →（必要時）方案判斷表 → 三個判斷原則（包含對應檢查）→ 情境例子 → 自己試試看 → 學完能產出**。

## 3｜文字品質與去重規則

- **先講結論，後補理由**：每項原則第一句能獨立成立，避免抽象長篇開場。
- **一段只服務一件事**：四段資源介紹交代定位與限制；章節負責教方法；案例示範使用；練習負責產出。
- **有比較才有決策價值**：如一般程式、單次模型、RAG、Workflow、Agent，應說明各自的必要條件，不能一律推最高複雜度。
- **講到可執行的層級**：優先寫前提、步驟、限制、反例、驗收；不要只重述來源目錄或行銷介紹。
- **可追溯且誠實**：不發明測試結果、來源、授權、能力或成功率。原文無法確認的事，標記待核實。
- **避免同義重複**：摘要、表格、原則、檢查、案例、練習各有功能；任何相鄰兩區若只是換句話說，應整併或刪除。
- **內容長度依資訊密度決定**：以讀者可以快速掃讀、又能真的操作為準，不為湊字數增加模糊敘述。

## 4｜資料欄位對應

| 內容區塊 | Canonical 資料欄位 |
|---|---|
| 適合什麼情境 | resource.recommendation |
| 主要功能 | resource.features[] |
| 使用條件 | resource.requirements[] |
| 限制與注意事項 | resource.limitations[] |
| 章節名稱、學習標籤、核心問題 | learningGuide.modules[].title / group / question |
| 需求／方案表 | learningGuide.modules[].decisionTable[]（可省略） |
| 三個判斷原則 | learningGuide.modules[].essentials[] |
| 對應檢查 | learningGuide.modules[].decisionChecks[]（可省略，內嵌顯示） |
| 情境例子 | learningGuide.modules[].example |
| 自己試試看 | learningGuide.modules[].apply |
| 學完能產出 | learningGuide.modules[].output |
| 整體練習 | learningGuide.practice |
| 章節來源 | learningGuide.modules[].sourceUrl |

現有可選 learningGuide 的舊欄位可以保留作資料紀錄；**不要因為有 outcomes 或 readingPath 就自動重複顯示摘要區塊**。欄位未來如有 Schema 改動，先確認既有資料與讀取程式相容。

## 5｜網站排版標準

- 桌面雙欄章節卡片的 **「情境例子」、「自己試試看」、「學完能產出」同列對齊**；兩欄文字長度不同也不得造成垂直起點錯亂。
- 行動裝置使用單欄自然閱讀，不為追求左右齊高而留下大塊空白。
- 顏色只區分資訊功能：原則／示例／練習／產物；避免同一資訊重複強調。
- 不把正文藏在每章都必須點擊展開的容器內；來源可以選讀展開。
- 檢查 375px、430px、768px、1440px 是否可讀、無橫向溢出、內容未被裁切。

## 6｜交付驗收（必做）

- **Scope**：只改指定教材或其共用樣式的必要部分；確認其他 Resource 未受到非預期影響。
- **Content**：每章能清楚回答問題，有選擇依據、具體案例、練習與可檢查產物。
- **Duplication**：沒有重複介紹；Agent 判斷問題已融入三個原則而非另一個重複區。
- **Source**：所有事實可追溯，第三方文章與原始專案分清楚；保留原始 URL、版本與限制。
- **Code**：JSON／Schema／References／JavaScript 語法可通過檢查，舊資源與 ID 不遺失。
- **Layout**：桌面卡片關鍵區塊對齊，行動裝置文字易讀。
- **Release**：GitHub Commit 不等於 GitHub Pages 已部署；未從公開網頁核對最新腳本／內容之前，不回報「網站完成」。

## 7｜日後建立教材的固定指令

> 請依 docs/LEARNING_CONTENT_SPEC.md 整理這份學習資源。先核對來源與版本，確認它適合建立教學型 Resource，再依「資源適用情境／主要功能／使用條件／限制」開場。各章沿用「AI 系統設計」的教學品質：一個核心問題、必要時的需求與方案比較、三個不重複的判斷原則、內嵌檢查、具體情境、可操作練習及可驗收產物。不要重複摘要或硬塞 Agent／決策表。保留原始連結，修改 Canonical 資料後執行驗證；無法確認之處標示未驗證。
